## 登录页报"用户名或密码错误"（20:43）

- 用户已在 AuthGlobalFilter 里补上 `user-info` 头传递（代码正确，白名单分支在前面，不影响 /users/login）。
- **真实原因：网关没启动**，8080 无监听 → 前端请求连接失败 → 页面显示通用文案"用户名或密码错误"。
- 证据：user-service 日志里当时没有该请求；启动网关后用空 body POST `/users/login` → 400 且 user-service 记录 `MethodArgumentNotValidException`，证明白名单放行 + 转发正常。
- 排查经验：前端登录失败先看 Network 是 `ERR_CONNECTION_REFUSED` 还是 4xx/5xx，别信页面文案；再对照后端日志有没有收到请求。

## cart 调用 item 报 503（21:18）

- 现象：`No servers available for service: item-service` / `Load balancer does not contain an instance for the service item-service` → Feign 503。
- 原因：**item-service 没启动**。查 Nacos `/v1/ns/service/list` 只有 `gateway`、`cart-service`；端口 8081/8084/8085 均未监听。
- 验证：临时启动 item-service（8081）后，同样请求经网关 8080 → cart(8082) → item(8081) 返回 200，数据里 newPrice/status/stock 齐全。
- 顺带确认：用户新加的用户信息传递链路已生效，cart 日志有 `userInfo=1`，SQL 用 `user_id = 1` 查到记录。
- 排查口诀：Feign 503 + "No servers available" 一律先去 Nacos 服务列表确认目标服务在不在，别怀疑代码。

## 购物车商品勾选不上（21:36）

- 现象：购物车那条"巴布豆"商品勾选框是禁用的，右侧红字"商品已经下架"，底部"已选择0件商品"。
- 原因：`hm-item`.item 里 id=100000006163 的 `status=2`（下架），前端对 status!=1 的商品禁用勾选。全库 88476 条商品里只有这 1 条是 2，恰好就是购物车里那条。
- 处理：`UPDATE \`hm-item\`.item SET status=1 WHERE id=100000006163;` 改回上架，刷新页面即可勾选。
- 也可以走接口：`PUT /items/status/{id}/{status}`（item-service ItemController.updateItemStatus）。

## 收银台一点"提交订单"就"支付超时"（21:48）

两个叠加的坑：

1. **前端写死默认订单**：`F:\Code\hmall-nginx\html\hmall-portal\pay.html` 的 `data()` 里 `order: {id: 458010519, totalFee: 298400, paymentType: 3}` 是默认值。截图里的"订单号 458010519 / ¥2984.00"就是它，不是真实订单。真实订单是 2120151370211823617 / 671 分。
2. **axios 超时只有 2 秒**（`js/common.js`: `axios.defaults.timeout = 2000`）。查订单失败时走 `.catch(err => console.log(err))` 静默吞掉，order 保持默认值 → `new Date(undefined).getTime()` = NaN → `setTimeout(fn, NaN - now)` 立即执行 → 弹"支付超时！"。
3. **时区错位 16 小时**：虚拟机系统时区是 PST，MySQL `time_zone=SYSTEM`，而 JDBC URL 写 `serverTimezone=Asia/Shanghai`。订单 create_time 读出来是 05:46（实际 21:46）。即使查询成功，`deadLine = createTime + 30min` 也早已过期 → 同样立刻超时。

修复：`SET GLOBAL time_zone='+08:00'` + 写 `/etc/my.cnf` 的 `default-time-zone='+08:00'` + 重启 mysql。
验证：同一订单接口现在返回 `createTime: 2026-11-10T21:46:19`（旧数据也跟着变对了，因为 TIMESTAMP 内部存 UTC），接口耗时 110ms。

- 端口/服务：gateway 8080、item 8081、cart 8082、user 8084、trade 8085、pay 8086；前端 nginx 在 80 / 18080(portal) / 18081(admin) / 18082，`/api` 反代到 8080。
- 顺带发现用户重复点了 4 次提交订单，生成 4 笔待支付订单（21:46:19 / 21:47:02 / 21:47:16 / 21:47:21）。
