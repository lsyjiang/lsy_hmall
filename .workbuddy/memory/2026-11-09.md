## Nacos 无法访问（192.168.100.128:8848 超时）

- 现象：浏览器访问 `http://192.168.100.128:8848/nacos` 报 `ERR_CONNECTION_TIMED_OUT`。
- Nacos 本身正常：docker 容器 `nacos` Up，本机 `curl 127.0.0.1:8848` 和 `curl 192.168.100.128:8848` 都返回 200。
- **根因：`net.ipv4.ip_forward = 0`**。Docker 发布的端口需要内核转发才能在宿主机侧访问；VM 内自访问走回环不经 FORWARD，所以本机正常、外部超时。MySQL 3306 是原生进程（走 INPUT）因此一直正常。
- 次要原因：firewalld 运行态只放行 3306/80（8848 在 permanent 里但没 reload）。
- 修复：
  1. `sysctl -w net.ipv4.ip_forward=1`，并写入 `/etc/sysctl.conf` 持久化；
  2. `firewall-cmd --permanent --add-port=8848,9848,9849/tcp && firewall-cmd --reload`；
  3. `systemctl restart docker` 重建转发规则。
- 验证：宿主机 Test-NetConnection 8848/9848/9849 全部 True，`http://192.168.100.128:8848/nacos/` 返回 200（登录页 2740 字节）。
- 备注：Nacos 是 docker 单机模式（`-Dnacos.standalone=true`，external storage，库应为 nacos）；容器端口 8848/9848/9849。

## item-service 注册 Nacos 失败

- 现象：启动日志反复 `Try to connect to server ... serverIp = '127.0.0.1', port 8848` → `Connection refused: /127.0.0.1:9848`，注册失败、`namingService subscribe failed`，上下文回滚。
- 原因：`spring.cloud.nacos.server-addr` 未配置，默认 127.0.0.1:8848；服务跑在 Windows，Nacos 在虚拟机。
- 修复：在 `item-service/src/main/resources/application.yaml` 的 `spring:` 下新增
  ```yaml
  cloud:
    nacos:
      server-addr: 192.168.100.128:8848
  ```
- 验证：`mvn spring-boot:run` 启动后，`GET http://192.168.100.128:8848/nacos/v1/ns/instance/list?serviceName=item-service` 返回 hosts 一条（ip=192.168.255.1, port=8081, healthy=true）。
- 注意：注册 IP 被 InetUtils 选成 `192.168.255.1`（VMware VMnet1），日志有 `Cannot determine local hostname`；本机互通没问题，若要跨机访问需显式配 `spring.cloud.nacos.discovery.ip`。
- cart-service 目前 pom 还没有 nacos-discovery 依赖，接注册中心时要一并加。

## IDEA Services 面板不显示端口号（16:20）

- 现象：8081/8082/8083 三个服务都在跑（端口已监听），但 Services 面板里不显示 `:端口/` 链接，也没有课程截图里的 Running / Not Started 分组。

- 分组说明：2025.2+ 起 IDEA 会保留 Finished 分组；右键 Finished → Clear Content 可让其回到 Not Started。

## cart-service Feign 调用 NPE

- 现象：`GET /carts` 报 `NullPointerException: this.itemClient is null`（CartServiceImpl.handleCartItems:118）。
- 原因：`CartServiceImpl` 用了 `@RequiredArgsConstructor`，但字段写成 `private ItemClient itemClient;`（**少了 final**，也没有 @Autowired），Lombok 不会把它放进构造器 → 注入不上，运行时为 null。
- 修复：改为 `private final ItemClient itemClient;`。javap 确认构造器变为 `CartServiceImpl(ItemClient)`。
- 其余配置本就正确：CartApplication 有 `@EnableFeignClients`；ItemClient 为 `@FeignClient("item-service")` + `@GetMapping("/items")`；pom 有 nacos-discovery / openfeign / loadbalancer；application.yaml 有 `spring.cloud.nacos.server-addr: 192.168.100.128:8848`。
- 验证：8084 起临时实例，`GET /carts` 返回 `newPrice:67100, status:2, stock:10000`（来自 item-service），HTTP 200。验证后已停实例。
- 经验：本项目所有 `@RequiredArgsConstructor` 的服务类，依赖字段必须写 `final`，否则静默为 null。

## user-service 登录报"用户名错误"（21:50）

- 日志关键行：`UserMapper.selectOne ==> Parameters: (String)` + `Total: 0` → 说明传入的 username 是**空字符串**（非 null，null 会打印 `null`）。
- 数据库没问题：`hm-user`.user 有 Jack/Rose/Hope/Thomas，哈希与 hmall 库一致（明文 123）。
- 根因：`LoginFormDTO` 用的是 `@NotNull`，空串能通过校验 → 空串进 SQL → 查不到 → `Assert.notNull` 抛 `IllegalArgumentException: 用户名错误`（500）。
- 已改：`@NotNull` → `@NotBlank`（username、password），空串会直接 400「用户名不能为空」，不再误导。编译通过，需重启生效。
- 待查：空串来自客户端（可能 Knife4j 调试未填，或前端请求地址/参数问题，注意 user-service 端口是 8084）。
