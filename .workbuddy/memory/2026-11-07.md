## 虚拟机 MySQL 修复（21:35-21:50）

- 虚拟机 `192.168.100.128`：CentOS 7 + kernel 3.10，root 密码 1234，SSH 22 可登。
- **两套 MySQL 冲突**：原生 MySQL 8.0.30 装在 `/usr/local/mysql`（systemd 单位 `/etc/rc.d/init.d/mysql`，开机自启），占用 3306；用户又创建了 docker 容器 `mysql`（端口映射 3306），因 3306 被占一直停在 `Created` 状态，从未启动过。
- 建库脚本在 `/root/mysql/init/hmall.sql`（8.8 万行，含 `CREATE DATABASE hmall`）。
- 修复动作：`--skip-grant-tables` 在该版本无效（仍报 1045），改用 `mysqld_safe --init-file=/tmp/init.sql` 重置；root@localhost 与 root@% 均设为 `mysql_native_password` + 密码 `123`；导入 hmall.sql（8 张表、88476 条商品）；最后交回 `systemctl start mysql`，状态 active、开机自启 enabled。
- 结果：宿主 `mysql -h 192.168.100.128 -uroot -p123` 可连，`GET /items/page` 返回 total 88476，**`hm.db.pw: 123` 无需再改**。
- 遗留：docker 容器 `mysql` 仍是 Created 状态，未删除（与原生实例抢 3306，若要改用 docker 需先停原生 mysql）。

## 账号与登录问题（21:55）

- `hmall.user` 共 4 条：Jack / Rose / Hope / Thomas，密码列是同一个 BCrypt 哈希 `$2a$10$6ptTq3V9...`，用 BCryptPasswordEncoder 实测明文为 `123`。**用户名是 Jack（大写 J）**，DB 排序规则不区分大小写，小写 jack 也能查到。
- 登录接口 500 的真正原因（见 `logs/hm-service/spring.log`）：MyBatis-Plus 3.4.3 的 `lambdaQuery()` 在 JDK 17 下访问 `SerializedLambda.capturingClass` 抛 `InaccessibleObjectException`，需 JVM 参数 `--add-opens java.base/java.lang.invoke=ALL-UNNAMED`。
- 已把该参数加进 `.idea/runConfigurations/HMallApplication_local.xml` 的 `VM_PARAMETERS`；另起 8081 实例带参数启动正常（旧 8080 实例无此参数，登录仍 500，需重启）。
- 为跑通 `mvn spring-boot:run` 验证，已向本地仓库安装 `com.heima:hmall:1.0.0`(父 pom) 与 `hm-common:1.0.0`。
- 副作用：root@'%' 改成 mysql_native_password 后，本机 MySQL 9.7 客户端连不上（9.x 已移除该插件），Java 侧 connector 8.0.23 正常。
- 应用日志位置：`F:\Code\hmall\logs\hm-service\spring.log`（由 logging.file.path 配置）。

## --add-opens 生效验证（22:30）

- 用 `mvn -f hm-service/pom.xml spring-boot:run -Dspring-boot.run.jvmArguments="--add-opens java.base/java.lang.invoke=ALL-UNNAMED" -Dspring-boot.run.arguments="--server.port=8080 --spring.profiles.active=local"` 启动成功。
- 注意：不显式给 `--server.port=8080` 时端口会被解析成随机值（曾出现 64182）导致 PortInUse 启动失败，显式指定即可。
- 验证手段：`GET /search/list`（SearchController 用了 `lambdaQuery()`，且在 excludePaths 里免登录）从 500 变 200，说明 SerializedLambda 反射问题已解决。
